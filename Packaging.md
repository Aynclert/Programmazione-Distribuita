Per essere distribuiti in un contenitore, i componenti devono prima essere impacchettati in un archivio standard formattato. Java EE definisce diversi tipi di moduli che hanno il proprio formato di pacchettizzazione basato sul formato *jar*.

- **Modulo client** dell'applicazione contiene classi Java e altri file di risorse contenuti in un file *jar* che può essere eseguito in un ambiente Java SE o in un contenitore client dell'applicazione. Il file *jar* contiene una directory META-INF opzionale per le meta-informazioni che descrivono l'archivio. Il file `META-INF/MANIFEST.MF` viene utilizzato per definire i dati relativi all'estensione e ai pacchetti.  Se distribuito in un #contenitori del client delle applicazioni (ACC), il descrittore di deployment può essere posizionato opzionalmente su `META-INF/application-client.xml`.
- **Modulo EJB**: contiene uno o più session e/o bean message-driven racchiusi in un file *jar*, contiene anche un descrittore `META-INF/ejb-jar.xml` facoltativo che può essere distribuito solo in un contenitore EJB.
- **Modulo di applicazione web**: contiene servlet, JSP, pagine JSF e servizi web, e tutti i file relativi al web. Tutti questi artefatti sono racchiusi in un file *jar* con estensione **.war**. Il descrittore di distribuzione web è `WEB-INF/web.xml`. Se il war contiene bean EJB Lite si può impostare `WEB-INF/ejb-jar.xml`. I file *Java.class* vengono posizionati nella directory `WEB-INF/classes` ed i file *jar* dipendenti nella directory `WEB-INF/lib`.
- **Modulo di business**: può contenere zero o più moduli di applicazioni Web, zero o più moduli EJB e altre librerie comuni o esterne. Tutto questo è impacchettato in un archivio business (*.ear*) in modo che la distribuzione di questi vari moduli avvenga simultaneamente e in modo coerente. Il descrittore di distribuzione opzionale è `META-INF/application.xml`.  La directory lib speciale viene utilizzata per condividere le librerie comuni tra i moduli.
